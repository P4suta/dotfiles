# Require applicable recommendations

## Context

Advisory wording permits an agent to omit useful guidance without evidence.
Source recommendations also contain conditions and alternatives that can't all govern every artifact.

## Decision

Treat applicable recommendations in shared skills and governing primary sources as required completion criteria.
Determine applicability from the task, platform, source conditions, and explicit requirements.
Preserve the source's original normative status while identifying adoption as owner policy.
Apply each relevant rule and verify its result without a separate evidence submission.
Resolve conflicts explicitly and justify exclusions.
An unresolved applicable rule blocks a completion claim.
Executable requirements use maintained project gates with rejecting fixtures.
Semantic suitability remains a direct review obligation.

## Alternatives

Keeping recommendations advisory preserves discretion but permits unexplained omissions.
Applying every recommendation unconditionally disregards source conditions and creates contradictory obligations.

## Consequences

The common agent policy governs existing skills without duplicating their instructions.
Interface skills require a complete source-to-verification review.
Direct review adds effort for semantic judgments.
Reconsider when recurring applicability disputes reveal a missing domain rule.

## Confirmation

Validate shared skills, generated instructions, and native installation.
Review observable requirements, rejecting fixtures, semantic judgments, and proposal boundaries in realistic interface tasks.
Keep the record proposed pending review.
