# Proof-first Scope Evaluation

The completion policy requires an assessment for every implementation change and source-bound proofs for supported deterministic properties.
Alternatives are mandatory evidence at defined boundaries, not a global opt-out or a way to relabel a failed proof.
The shared entry point routes tool-specific material to conditional references and keeps project facts out of the skill.

| Realistic task | Required decision | Regression evidence |
| --- | --- | --- |
| Change finite coordinate arithmetic | Import the production helper into a native proof over all admitted values | Missing, failed, unreachable and stale proof results are rejected by the native gate |
| Preserve reciprocal assignment arrays | Decompose the actual body into all assignment-state cases and quantify an arbitrary index | Five direct Rust proofs establish exact updates and framing; initial completed attempts took 6–13 seconds after the whole-array contract had timed out |
| Change a GPU heuristic with a finishing cap | Prove deterministic invariants and require known-key recovery plus the same search on shuffled controls | The Lean counterexample rejects unconditional candidate retention; hardware records require exact test commands and one executed passing test |
| Verify an HTTP or cloud adapter | Prove supported decisions, state external semantics and require native integration and failure checks | Classification cannot use a timeout as its reason; omission, duplicates, empty rationale and missing controls fail the assessment |
| Add a theorem about a small abstract graph | Record its model bound and implementation refinement before claiming production coverage | An exploratory four-edge theorem cannot discharge a required production contract or authorize complete search |

The companion implementation in cipher-break binds each required result to its production sources and retains separate scoped-completion and whole-search checks.
Its targeted rejection regressions and the source-importing admission proof exercise the decisions above.
The catalog checks validate names, frontmatter, references and shared discovery aliases; native rollout checks inspect the installed content and preserve existing client authentication and observation history.
This evaluation records observed scenarios rather than asserting that prose validation proves instruction compliance.
