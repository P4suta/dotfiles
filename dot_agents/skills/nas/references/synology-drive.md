# Synology client transport

Locate the installed client's configured sync root on each operating system.
On-demand files can stay placeholders, so hydrate required inputs before archiving and verify that the archive read every intended byte.
After upload, read the client or server's per-file status and error details, not the folder badge.
On macOS, the native File Provider's read-only item evaluation reports `isUploaded`, `isUploading`, `isSyncPaused`, conflict, and exclusion states when the interface stays out of reach.
Record that as a provider acknowledgment, never a server-side checksum or independent restore.
Preserve the existing task and authentication, because changing or removing a sync task can affect local and remote content.

Use the current [client documentation](https://kb.synology.com/en-us/DSM/help/SynologyDriveClient/synologydriveclient?version=7), [on-demand sync guidance](https://kb.synology.com/en-us/DSM/tutorial/What_is_On-demand_Sync), and [sync failure diagnostics](https://kb.synology.com/DSM/tutorial/Why_are_files_not_synced_between_Synology_Drive_and_Drive_desktop_application) for the installed version.
