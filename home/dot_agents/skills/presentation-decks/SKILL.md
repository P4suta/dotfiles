# Presentation decks

A spoken slide serves the listener, and an appendix serves the reader.
A listener can either read a slide or listen to the speaker, so a spoken slide carries the words the speaker says.
Use monochrome-design for the visual style, or github-style-slides when the owner asks for the GitHub look.
Read [Figma Slides](references/figma-slides.md) when the deck lives in Figma Slides.

## Brief

Record the audience, what they already know, the talk length, the question time, and whether they receive the deck in advance.
State the one message the talk must leave and the decision or impression it should produce.
Lead with results when the audience comes from outside the team.
Show growth through decisions inside the work instead of self-description.

## Time budget

Derive the slide count from the talk length, starting from about 25 seconds per spoken slide.
Replace the estimate with a timed reading once the script exists.
When a slide gains content, add its script and offset the time by merging or moving another slide.

## Structure

Split the deck into a spoken main part and an appendix for reading.
Close the argument in the main part: problem, constraint, decision criteria, actions, results, lesson, and next steps.
A closed argument keeps the appendix details in the appendix.
List all the work with each item's actual status, and mark the items the talk covers.
Keep the title page, the overview, and the summary from presenting the covered items as the whole of the work.
State each status as it stands, such as stopped before production, unmerged, or prototype.
Put a results summary that shows each outcome side by side before the lessons, with the remaining work beside it.
Define each specialist term on the slide where it first appears.
Report results with measured numbers, and leave a number out instead of inventing one.
Point each main slide to its appendix page with a small reference, and mention the appendix once at the start of the talk.
Keep superseded slides in a separate skipped section instead of deleting them.

## Script first

Write the full script before building any slide.
Give each spoken slide a title that states its message in one sentence and one figure that supports it.
Draw the figure from words in the script, and make it readable in about three seconds.
Read the titles in sequence and repair any gap in the argument they summarize.
Choose the figure from the relationship it shows: a sequence, a comparison, a change, a structure, or a real example.
Store the script in the speaker notes of each slide.

## Verification

Compare every phrase on each spoken slide with that slide's script and resolve each phrase the script lacks.
Read the script aloud and compare its duration with the slot.
Check that the speaker notes hold the current script and that page counters follow the slide order.
Capture each changed slide and inspect clipping, overlap, and connectors that miss their targets.
Review the deck from distinct viewpoints, such as an outside listener, a domain reviewer, and title, figure, and script consistency.
Repeat the review until a round finds no new issue.
Report each check that you didn't run.
